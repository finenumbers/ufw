# История операций

Долгие задачи (применение, обновление, установка UFW, тест SSH) отслеживаются в **журналах операций** и отображаются в интерфейсе.

## Баннер операции

Пока операция выполняется, в верхней части приложения появляется баннер:

- Тип операции и статус (RUNNING, SUCCESS, FAILED)
- Разворачиваемый список шагов со статусом каждого шага
- Автоматическое закрытие при успехе после короткой задержки

Баннер опрашивает обновления во время выполнения работы.

Если баннер завис на **RUNNING** или **PENDING** после отключения браузера, обновите страницу. Устаревшие операции автоматически очищаются фоновым sweep (обычно в течение 30–60 минут).

## Страница операций

Боковая панель → **История операций** (`/operations`)

Две вкладки:

| Вкладка | Содержимое |
|---------|------------|
| **Операции** | Технический журнал операций — применение, sync, тест SSH и т.д. |
| **Аудит** | События, связанные с безопасностью — вход, выход, экспорт конфигурации |

Обе поддерживают бесконечную прокрутку для более старых записей.

## Типы операций

Примеры:

- `apply_rules` — применение UFW
- `ufw_refresh` — обновление статуса и правил
- `ufw_sync` — синхронизация черновика с сервером
- `ufw_install` / `ufw_enable` — настройка UFW
- `ssh_test` — проверка подключения
- `server_create` — добавлен новый сервер

## Очистка истории

Администраторы могут очистить старую историю операций в интерфейсе (события аудита могут сохраняться согласно политике retention). Очистка не влияет на состояние сервера или правила.
