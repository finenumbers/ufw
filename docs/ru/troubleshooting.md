# Устранение неполадок

Симптом → вероятная причина → что делать.

## Аутентификация

| Симптом | Причина | Решение |
|---------|---------|---------|
| Цикл перенаправлений при входе | Несовпадение `APP_URL` с URL в браузере | Задайте `APP_URL` точно как публичный HTTPS URL; перезапустите приложение |
| Вход работает локально, но не через домен | NPM или флаг secure у cookie | Force SSL в NPM; проверьте, что схема `APP_URL` — `https://` |
| `BETTER_AUTH_SECRET is required` | `.env` не загружен | Используйте `--env-file .env` в compose |

## Docker / NPM

| Симптом | Причина | Решение |
|---------|---------|---------|
| NPM 502 Bad Gateway | Приложение не в сети NPM | Задайте `NPM_NETWORK`; проверьте, что `ufw-app` подключён к внешней сети |
| `ufw-app` unhealthy | БД недоступна или отсутствуют секреты | Проверьте `docker logs ufw-app`, health postgres |
| `ufw-migrate` failed | Ошибка миграции | Прочитайте `docker logs ufw-migrate`; при необходимости восстановите из резервной копии |
| `pull access denied` | Приватный пакет GHCR | Сделайте пакет Public или выполните `docker login ghcr.io` |

## SSH

| Симптом | Причина | Решение |
|---------|---------|---------|
| Проверка SSH не проходит | Неверные учётные данные, межсетевой экран, хост недоступен | Проверьте идентификацию, порт, разрешает ли сервер IP Docker-хоста |
| Ошибка проверки хоста | Частный IP заблокирован | Задайте `SSH_ALLOWED_CIDRS` для внутренних сетей |
| Host key изменился | Переустановка сервера или MITM | Проверьте отпечаток на сервере; обновите после подтверждения |
| Непроверенный host key | Импортирован из конфигурации | Выполните проверку SSH на странице редактирования сервера |

## Правила / применение

| Симптом | Причина | Решение |
|---------|---------|---------|
| Страница правил пуста / недоступна | UFW не активен | Установите и включите UFW с панели управления |
| Предпросмотр показывает неожиданные удаления | Расхождение черновика | Принудительная синхронизация с сервером |
| Предупреждение о частичном применении | Предыдущее применение прервано | Синхронизация; проверьте удалённый `ufw status` вручную |
| Потерян доступ по SSH | Применено правило deny | Консоль/внеполосный доступ; исправьте UFW на сервере напрямую |

## Данные

| Симптом | Причина | Решение |
|---------|---------|---------|
| Учётные данные недействительны после восстановления | Неверный `APP_ENCRYPTION_KEY` | Восстановите соответствующий `.env` из резервной копии |
| Не удаётся расшифровать идентификации | Ротация ключа без повторного ввода | Повторно введите секреты или восстановите экспорт JSON |

## Health API

```bash
docker exec ufw-app node -e "fetch('http://127.0.0.1:3000/api/health').then(r=>r.json()).then(console.log)"
```

Ожидается: `{"status":"ok","db":"ok"}`
