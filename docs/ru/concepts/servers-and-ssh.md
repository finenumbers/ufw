# Серверы и SSH

Запись **server** представляет один управляемый Linux-хост. Приложение подключается по SSH для команд UFW и чтения состояния firewall.

## Поля сервера

| Поле | Назначение |
|------|------------|
| **Name** | Отображаемое имя в боковом меню |
| **Host** | IP или DNS (проверяется перед сохранением) |
| **Port** | SSH-порт (по умолчанию 22) |
| **SSH identity** | Учётные данные для подключения |

## Валидация host (защита от SSRF)

Перед сохранением сервера host проверяется:

- Частные диапазоны IP (10.x, 172.16–31, 192.168.x) **заблокированы** по умолчанию
- Link-local и metadata-адреса облака заблокированы
- IPv4-mapped частные IPv6 заблокированы
- Опциональный allowlist: `SSH_ALLOWED_CIDRS` в `.env`

Это предотвращает использование приложения как прокси для сканирования внутренних сетей.

## Проверка DNS-резолва

1. **При сохранении** — проверяется строка hostname
2. **Перед connect** — hostname резолвится в IP и **резолвленный адрес** проверяется теми же правилами

Это закрывает DNS rebinding, когда публичный hostname позже резолвится в частный или metadata IP.

## SSH-проверка при сохранении

При создании или обновлении сервера (host, port или смена identity) **SSH-проверка выполняется автоматически при submit**. Отдельной кнопки test нет — сохранение блокируется до успешной проверки.

При первой успешной проверке сохраняется fingerprint host key, сервер помечается **verified**.

## Pinning SSH host key

| Состояние | Значение |
|-----------|----------|
| **Verified** | Ключ записан после успешного save при create/update или **Обновить статус** |
| **Unverified** | Ключ импортирован из конфигурации — выполните **Обновить статус** на dashboard сервера |

На странице редактирования показывается fingerprint и предупреждение unverified; проверка при изменении параметров подключения — только при save или **Обновить статус** на dashboard.

При смене host key на сервере (reinstall, MITM) следующее подключение завершится ошибкой до расследования.

## Что делает удаление сервера

Удаление сервера удаляет **только локальные** данные:

- Черновики, snapshots, apply sessions, история операций

**Не** изменяет правила UFW на удалённом Linux-хосте.

## Жизненный цикл UFW на сервере

На dashboard сервера:

1. **Обновить статус** — установлен ли и активен ли UFW (до refresh — кэш snapshot)
2. **Установить UFW** при отсутствии — install и enable в одной операции
3. Редактирование и apply правил, когда UFW установлен **и** активен

Редактирование правил доступно только когда UFW установлен **и** активен.
