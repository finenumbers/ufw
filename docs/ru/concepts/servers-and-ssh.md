# Серверы и SSH

Запись **сервера** представляет один управляемый Linux-хост. Приложение подключается по SSH для выполнения команд UFW и чтения состояния межсетевого экрана.

## Поля сервера

| Поле | Назначение |
|------|------------|
| **Имя** | Отображаемая метка в боковой панели |
| **Хост** | IP-адрес или DNS-имя (проверяется перед сохранением) |
| **Порт** | SSH-порт (по умолчанию 22) |
| **SSH-идентификация** | Учётные данные для подключения |

## Проверка хоста (защита от SSRF)

Перед сохранением сервера хост проходит проверку:

- Частные диапазоны IP (10.x, 172.16–31, 192.168.x) **блокируются** по умолчанию
- Link-local и адреса облачных metadata блокируются
- Частные IPv4-mapped IPv6 адреса блокируются
- Опциональный allowlist: задайте `SSH_ALLOWED_CIDRS` в `.env` (например, `10.0.0.0/8`) для внутренних сетей

Это предотвращает использование приложения как прокси для сканирования внутренних сетей.

## Проверка DNS-резолва

Проверка выполняется в два этапа:

1. **При сохранении** — проверяется строка hostname (частные литералы, metadata-хосты, опциональный CIDR allowlist).
2. **Перед подключением** — hostname резолвится в IP, и **резолвленный адрес** проверяется по тем же правилам.

Это закрывает пробелы DNS rebinding, когда публичный hostname позже резолвится в частный или metadata IP.

## Проверка SSH перед сохранением

Создание или обновление сервера (изменение хоста, порта или идентификации) требует успешной **проверки SSH-подключения**. Интерфейс блокирует сохранение, пока проверка не пройдёт.

## Закрепление SSH host key

При первом успешном подключении сохраняется отпечаток SSH host key сервера.

| Состояние | Значение |
|-----------|----------|
| **Verified** | Ключ записан после успешной проверки SSH или обычной операции |
| **Unverified** | Ключ импортирован из файла конфигурации — выполните проверку SSH для верификации |

Если удалённый host key изменится (переустановка, MITM), следующее подключение завершится ошибкой, пока вы не разберётесь с причиной.

## Что делает удаление сервера

Удаление сервера удаляет **только локальные** данные:

- Черновики правил, снимки, сессии применения, история операций для этого сервера

Это **не** меняет правила UFW на удалённом Linux-хосте. Состояние удалённого межсетевого экрана остаётся прежним.

## Жизненный цикл UFW на сервере

С панели управления сервером вы можете:

1. **Определить** UFW — установлен? активен?
2. **Установить** UFW, если отсутствует
3. **Включить** UFW и синхронизировать правила

Редактирование правил доступно только когда UFW **установлен и активен**.
