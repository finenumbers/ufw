# Введение

**UFW Remote Manager** — самостоятельно размещаемое веб-приложение для управления **UFW (Uncomplicated Firewall)** на удалённых Linux-серверах по **SSH**. Вы редактируете правила межсетевого экрана в браузере, просматриваете изменения, явно подтверждаете их и безопасно применяете — с полным журналом аудита.

Репозиторий: [github.com/finenumbers/ufw](https://github.com/finenumbers/ufw) · Текущий релиз: **v0.9.2**

## Для кого этот продукт?

- **Системным администраторам**, управляющим несколькими Linux-серверами и предпочитающим структурированный интерфейс повторным сессиям CLI `ufw`
- **Небольшим командам**, которым нужно единое место для черновиков правил, предпросмотра apply и истории операций
- **Self-hosters**, размещающим инфраструктуру за reverse proxy (рекомендуется Nginx Proxy Manager)

## Что умеет приложение

| Возможность | Описание |
|-------------|----------|
| **Управление SSH** | Подключение по паролю или приватному ключу; закрепление host key при первом подключении |
| **Жизненный цикл UFW** | Удалённое определение, установка и включение UFW |
| **Таблица правил** | Редактирование с группами, именами, поиском, фильтрами, drag-and-drop reorder |
| **Черновик → apply** | Предпросмотр diff, подтверждение, выполнение команд UFW по SSH |
| **Быстрые dashboard** | Страницы серверов загружаются из кэшированных Postgres snapshots; live SSH только при обновлении |
| **Импорт / экспорт** | Правила из CSV, XLSX, JSON; полная конфигурация серверов + идентификаций как JSON v2 |
| **Сканирование портов (опционально)** | Внешнее TCP-сканирование с сопоставлением покрытия UFW |
| **Безопасность** | Шифрование учётных данных при хранении; audit log; step-up password для экспорта конфигурации |
| **Языки** | UI на английском, немецком, французском, испанском, итальянском, португальском (Бразилия), русском |

## Чего приложение не делает

| Ожидание | Реальность |
|----------|------------|
| Заменяет ваш reverse proxy | **Нет.** Nginx Proxy Manager (или аналог) завершает HTTPS отдельно |
| Управляет «сырыми» `iptables` без UFW | **Нет.** Ориентировано на серверы, где UFW — фронтенд межсетевого экрана |
| Инвентаризация / управление Docker-контейнерами | **Нет.** Удалено в v0.9.0 — не входит в текущий scope |
| Multi-tenant SaaS | **Нет.** Self-hosted с одним экземпляром; одна учётная запись администратора после настройки |
| Кластер высокой доступности | **Нет.** Рассчитано на **одну реплику приложения** (rate limits в памяти) |
| Автоматические изменения межсетевого экрана | **Нет.** Apply всегда требует явного подтверждения пользователя |

## Инвентарь и статистика

После v0.9.0 **инвентарь** в списке серверов означает:

- **Сохранённые правила** — количество правил в локальных метаданных (`ruleRecord`)
- **Открытые порты** — количество из последнего успешного внешнего сканирования (если включено)

Панели Docker-контейнеров и удалённого мониторинга контейнеров нет.

## Требования

### Хост управления (где работает Docker)

- Docker и Docker Compose
- Опционально: Portainer, уже установленный Nginx Proxy Manager
- Сеть из контейнера приложения к целевым серверам по SSH (порт 22 или пользовательский)
- Для scan портов: egress с хоста приложения на целевые TCP-порты (не только `:22`)

### Целевые серверы (управляемые Linux-хосты)

- Linux с доступным UFW (`apt install ufw` или эквивалент)
- SSH-доступ с правами на выполнение команд `ufw`
- SSH-порт доступен с хоста управления

### Продакшен

- Публичный **HTTPS** URL для админ-интерфейса (`APP_URL`)
- Надёжные секреты в `.env` (никогда не коммитить в git)
