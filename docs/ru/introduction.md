# Введение

**UFW Remote Manager** — самостоятельно размещаемое веб-приложение для управления **UFW (Uncomplicated Firewall)** на удалённых Linux-серверах по **SSH**. Вы редактируете правила межсетевого экрана в браузере, просматриваете изменения, явно подтверждаете их и безопасно применяете — с полным журналом аудита.

Репозиторий: [github.com/finenumbers/ufw](https://github.com/finenumbers/ufw)

## Для кого этот продукт?

- **Системным администраторам**, которые управляют несколькими Linux-серверами и предпочитают структурированный интерфейс ручным сессиям CLI `ufw`
- **Небольшим командам**, которым нужно единое место для черновиков правил, предпросмотра применения и истории операций
- **Self-hosters**, которые размещают собственную инфраструктуру за reverse proxy (рекомендуется Nginx Proxy Manager)

## Что умеет приложение

- Подключаться к Linux-серверам по SSH (пароль или приватный ключ)
- Удалённо определять, устанавливать и включать UFW
- Загружать актуальные правила UFW, редактировать их в таблице (с группами, именами, поиском, изменением порядка)
- Рабочий процесс **черновик → предпросмотр → подтверждение → применение** с визуализацией diff
- Импортировать правила из CSV, XLSX или JSON; экспортировать/импортировать полную конфигурацию серверов
- Шифровать SSH-учётные данные при хранении; закреплять SSH host keys; аудировать чувствительные действия
- Многоязычный интерфейс (английский, немецкий, французский, испанский, итальянский, португальский, русский)

## Чего приложение не делает

| Ожидание | Реальность |
|----------|------------|
| Заменяет ваш reverse proxy | **Нет.** Nginx Proxy Manager (или аналог) завершает HTTPS отдельно |
| Управляет «сырыми» `iptables` без UFW | **Нет.** Ориентировано на серверы, где UFW — фронтенд межсетевого экрана |
| Multi-tenant SaaS | **Нет.** Self-hosted с одним экземпляром; одна учётная запись администратора после настройки |
| Кластер высокой доступности | **Нет.** Рассчитано на **одну реплику приложения** (rate limits в памяти) |
| Автоматические изменения межсетевого экрана без подтверждения | **Нет.** Применение всегда требует явного подтверждения пользователя |

## Требования

### Хост управления (где работает Docker)

- Docker и Docker Compose
- Опционально: Portainer, уже установленный Nginx Proxy Manager
- Сетевой доступ из контейнера приложения к целевым серверам по SSH (порт 22 или пользовательский)

### Целевые серверы (управляемые Linux-хосты)

- Linux с доступным UFW (`apt install ufw` или эквивалент)
- SSH-доступ с достаточными правами для выполнения команд `ufw`
- Исходящая связность с хоста управления на SSH-порт сервера

### Продакшен

- Публичный **HTTPS** URL для админ-интерфейса (`APP_URL`)
- Надёжные секреты в `.env` (никогда не коммитить в git)
